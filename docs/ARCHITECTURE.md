# Curator Architecture

This is the map of how Curator is built, the contracts between its parts and the rules that keep it working. Read it before changing code. It describes what the code does today, so when behaviour changes, change this document in the same change.

## 1. Overview

Curator turns a folder of Markdown files of links and notes into a static website. Each link is a 35mm slide on a light table, and opening one drops it into a projector that shows the curator's notes on a pull-down screen.

Design principles:

- **Static output.** The build writes a folder of plain files that any static host can serve on its own domain or subdomain. There is no server code at runtime.
- **No runtime dependencies and no dev dependencies by default.** `package.json` has no `dependencies`. Anything new needs a clear reason.
- **No framework, bundler or TypeScript.** Plain JavaScript ES modules, in Node and in the browser. The browser loads the same files that sit in `src/`.
- **Config driven design values.** Every colour, font and timing comes from `curator.config.json` or from a CSS custom property with a default.
- **Node 20 or newer.** `.nvmrc` pins the version for hosts.
- **One source of truth for shared logic.** Code that both the build and the browser need lives in DOM free modules (section 4).

## 3. Build Pipeline

`npm run build` runs `scripts/build.mjs`, which calls `buildSite()` in `scripts/lib/build-site.mjs` and prints the result with `printIssues()` from `scripts/lib/report.mjs`. `npm run check` runs `scripts/check.mjs`, which stops after the first two steps below and writes nothing. `npm run dev` runs the same `buildSite()` and serves the result. All three accept `--root <dir>` to work on another project folder, which is how tests build fixtures.

```
curator.config.json --> 1 config --+
content/*.md -------> 2 content ---+--> checkSite() errors stop here
                                   |
                  3 images (cache, fetch, fit)
                  4 fonts (links, optional self hosting)
                  5 site data: posters, brand, site.json object
                                   |
   wipe outDir --> 6 assets with hash --> 7 site.json, favicon
                                   |
                  8 theme block --> 9 pages and heads --> 10 404, sitemap, robots
```

1. **Config load and validation** (`scripts/lib/config.mjs`). `loadConfig()` reads `curator.config.json` (a leading BOM is allowed), validates it against `src/config.schema.json` with a small built in validator (`validateConfig()`), then fills every missing value from the schema `default` (`resolveConfig()`). The validator supports `type`, `enum`, `pattern`, `minLength`, `minimum`, `maximum`, `minItems`, `maxItems`, `uniqueItems`, `items`, `anyOf`, `required`, `additionalProperties` and a custom `message`. Unknown keys fail with "is not a known setting". Errors are named by path, such as `advanced.posters.minContrast must be a number from 1 to 21`. If the config is invalid, content is not checked at all.
2. **Content parsing and validation** (`scripts/lib/parse.mjs`, `validate.mjs`, `markdown.mjs`). `readCollections()` parses every `content/*.md` leniently: front matter, `## ` headings as items, `key: value` field lines up to the first blank line, then notes. It records what it finds and never throws. `assignIds()` slugs titles and suffixes duplicates with `-2`, `-3`. Types come from `inferType()` in `src/js/types.js`. `validateSite()` then turns problems into errors (build stops) or warnings (build continues), each naming the file, the item and the fix. It also checks `collections.order`, `collections.default`, `advanced.types`, `advanced.scene.colors` against the real tokens, brand text contrast and `basic.site.socialImage`. Uploads and the social image are judged by their bytes, not only their names: `fileProblem()` reads the file and `imageSize()` must recognise it, the format must match the extension (`.jpg` and `.jpeg` both mean jpeg), and an SVG over 100 KB is refused. `socialImage` must also resolve inside the project root, end in `.png`, `.jpg`, `.jpeg`, `.gif` or `.webp`, and not be an SVG. `checkSite()` ties config and content together and is what both `check` and `build` call first. `markdown.mjs` renders the notes subset (paragraphs, emphasis, strong, code and `http` or `https` links) with raw HTML escaped, and produces the plain text used for descriptions.
3. **Images** (`scripts/lib/images.mjs`, `imagesize.mjs`). `resolveImages()` gives every item one of three outcomes. `none` gives a poster. A path resolves to the file under `content/`. `auto` looks in the cache `.cache/images.json` (keyed by the item URL, with files in `.cache/images/`) and otherwise fetches a preview: the video host thumbnail, the repository host card, the link itself when it serves an image (never SVG), or the page's `og:image` and then its card image meta tag. A response must be an image MIME type within `advanced.images.maxBytes`, and fetching stops after `timeoutMs`. Four fetches run at once. Every request goes through `guardedFetch()` in `scripts/lib/net.mjs`, which refuses a non public address at every hop: the link, each redirect (up to 5, followed by hand), the `og:image` address and the preview addresses. It refuses a scheme other than http or https, `localhost` names, loopback, private, link local and metadata addresses, and any host whose DNS answers include one. Every build time fetch resolves the host and checks every answer, whichever `fetch` is used, and refuses when the address cannot be checked. Known limit: a host can change its DNS answer between the lookup and the fetch (DNS rebinding), because Node's `fetch` cannot pin the address without a dependency. A refused or failed fetch becomes a warning and the item gets a poster. `imageSize()` reads width and height from PNG, JPEG, GIF, WebP and SVG headers with no dependency. The fit flag is true when the aspect ratio is wider than 1.75 to 1 or the domain is in `advanced.images.fitDomains`. Raster files are named by the first 16 hex of their content hash. `--refresh-images` refetches everything and `--refresh-images=<collection>/<item>` refetches one.
4. **Fonts** (`scripts/lib/fonts.mjs`). `resolveFonts()` collects the six role families (`collectFamilies()`), builds one URL for the hosted font service (`googleUrl()`, using known axis ranges for the default families and a probe for unknown ones, cached in `.cache/fonts.json`), and returns the HTML for the `{{fonts}}` slot. With `fonts.source` set to `self`, `selfHost()` downloads the stylesheet and font files into `.cache/fonts/`, rewrites the URLs to `/fonts/<hash>.woff2` and returns files to copy plus a stylesheet named `fonts-<hash>.css`. The stylesheet and font file requests use the same guard as images, so a font address that is not public is refused and the fonts fall back to system fonts. A family the service does not know is an error, and a failed download is a warning that falls back to system fonts. `checkFonts()` runs only the family check for `npm run check` and is skipped for `self` or a custom `googleFontsUrl`.
5. **Site data and posters** (`scripts/lib/site.mjs`). `buildSiteData()` orders collections, normalises the brand with `normalizeBrand()`, builds the palette with `buildPalette()` and, for each collection, assigns compositions to the items that need a poster with `assignPosters()`. Each such item gets `poster: { v, set, paper, inks, band }` from `palette.palette(title)`. It renders notes to HTML and text, collects raster image files under `/images/<hash>.<ext>`, embeds each uploaded SVG in `site.json` as a `data:image/svg+xml;base64,` address (no `.svg` file is published) and returns the `site.json` object (section 5) and the list of files to copy.
6. **Output folder and assets.** Before anything is written, `safeOutDir()` judges `advanced.build.outDir` (rules below). Then the folder is emptied and a `.curator-build` marker is written. `frontEnd()` lists every file under `src/` except `index.html` and `config.schema.json`, hashes their paths and contents with SHA-256 and keeps the first 10 hex. The files are copied to `dist/assets/<hash>/`, keeping their names, so a change to any front end file changes every asset URL. Raster image files go to `dist/images/` and font files to `dist/fonts/`.
7. **`site.json` and favicon.** `dist/data/site.json` is `JSON.stringify` of the data object. `dist/favicon.svg` comes from `faviconSvg()` in `scripts/lib/favicon.mjs`, a slide mount in primary 1 with a window in the light neutral.
8. **Theme block** (`scripts/lib/theme.mjs`). `computeRoles()` computes the brand driven values (section 9) and `themeStyle()` writes them, the font variables and the validated colour overrides into one `<style id="curator-theme">` block.
9. **Pages and heads** (`scripts/lib/html.mjs`). Every page is `src/index.html` with six placeholders replaced: `{{lang}}`, `{{head}}`, `{{assets}}` (`/assets/<hash>/`), `{{scene}}`, `{{theme}}` and `{{fonts}}`. The pages are `dist/index.html`, `dist/<collection>/index.html` and, unless `advanced.build.itemPages` is false, `dist/<collection>/<item>/index.html`. All pages are the same app shell. Only the head differs. `pageHead()` writes `<title>` through `pageTitle()` from `src/js/title.js`, the description, the canonical URL, Open Graph tags and card tags. An item uses the first 160 characters of its notes and its preview image, falling back to `basic.site.socialImage`. A collection uses its own description. Every value passes `escapeHtml()`.
10. **404, sitemap, robots.** `dist/404.html` is the same shell with a head that has only the "Not found" title, a description and `noindex`. `dist/sitemap.xml` lists the home page, collections and items. `dist/robots.txt` allows everything and names the sitemap.

**`outDir` safety.** The build deletes its output folder, so it refuses to touch anything it did not make. `safeOutDir()` rejects a folder that is the project root, is outside it, or is inside or contains any of `src`, `content`, `docs`, `scripts`, `tests`, `.cache`, `node_modules` or `.git`. `buildSite()` also refuses an existing folder that is not a directory or that holds files but no `.curator-build` marker. The check runs before images are fetched, so a refusal costs nothing. A failed build returns before the folder is touched, so the last good output stays.

**`--offline`.** With `--offline` (accepted by `build` and `check`), the build makes no network requests. Images come only from uploads and the cache, and fonts only from the font cache. Anything missing becomes a poster or a warning. Browser tests build with it. `advanced.images.fetch: false` has the same effect for images alone.

**Dev server** (`scripts/dev.mjs`). It builds once, serves the output with `startServer()` from `scripts/lib/serve.mjs` on port 4321 (`--port` or `PORT` to change it) and rebuilds 150ms after a change in `content/`, `src/` or the config file, ignoring `.cache/`. It remembers images that failed to fetch (`skipUrls`) so each rebuild does not retry them. If a build fails, the last good output keeps being served for assets while HTML requests answer with a 500 page that lists the errors. The server behaves like a static host: folder index files, a 301 for a folder without a trailing slash, `404.html` for a miss, and `Cache-Control: no-store`. A `mounts` map serves other folders under a prefix, and the dev and test servers mount `tests/browser/` at `/__tests/`. That mount never appears in `dist/`. The dev and test servers also serve the theme page at `/__theme/`, a reference for checking a brand before publishing. `dev` prints its URL after the serving line. It is a plain page in `scripts/theme-page/` that imports the shared modules from a `/__theme/js/` mount of `src/js/`, and reads `/data/site.json` and a `/__theme/data.json` route (`scripts/lib/theme-page.mjs`) that returns the colour tokens, the overrides, the poster targets and the computed roles of the configured brand and of `docs/examples/sample-brand.json`. `?brand=sample` switches the brand. None of it is built, and a unit test fails when `dist/` mentions it.

## 4. Shared Modules

`src/js/types.js`, `seed.js`, `palette.js`, `kit.js` and `title.js` are loaded by the browser as ES modules and imported by Node build scripts (`site.mjs`, `theme.mjs`, `parse.mjs`, `html.mjs` and others). They must stay DOM free: no `document`, `window` or other browser globals, and no `node:` imports.

Why this matters:

- **One answer in both places.** The build decides poster inks, composition numbers, content types and page titles, and the browser draws posters and sets the tab title. If the logic lived twice, the two could disagree. The tests call the same functions the pages use.
- **Determinism.** Everything is derived from a hash of the item (`hash()` and `rng()` in `seed.js`), so the same item always looks the same on every build and every visit.
- **Testability.** `node --test` can import them directly with no browser.

| Module | Provides |
|--------|----------|
| `types.js` | The content type registry `TYPES` (`video`, `repo`, `image`, `article`, `webpage`), `typeNames()`, `getType()` and `inferType()`. `webpage` must stay last because its matcher accepts everything. `article` is never inferred and only applies when an item sets `type: article` |
| `seed.js` | `hash()` (a 32 bit string hash) and `rng()` (a seeded random number generator) |
| `palette.js` | Colour maths (`mix`, `lum`, `contrast`), `normalizeBrand()` and `buildPalette()`, which turns a brand and the poster settings into deterministic poster inks |
| `kit.js` | The 16 poster compositions, `poster()` which returns inline SVG text, `assignPosters()` and `COUNT` and `NAMES` |
| `title.js` | `pageTitle()`, the one function for every page title, used by the build for heads and by `core.js` for `document.title` |

The build only calls `normalizeBrand()`, `buildPalette()` and `assignPosters()`. `poster()` runs in the browser, because the SVG is drawn at the size the scene asks for. It relies on the `#kit-grain` pattern that `core.js` defines.

## 5. `site.json`

`dist/data/site.json` is the only data the front end loads. It is written by `buildSiteData()` and contains everything the browser needs, so the browser never parses Markdown or reads directories. Annotated example (not valid JSON because of the comments):

```
{
  "version": 1,
  "site": {
    "title": "Sample brand", "description": "...", "language": "en",
    "url": "https://links.example.com",     // no trailing slash
    "socialImage": "/images/<hash>.png"      // or null
  },
  "scene": { "name": "lighttable", "pageSize": 12, "motion": "normal", "colors": {} },
  "fonts": { "display": "...", "body": "...", "mono": "...", "poster": "...", "typewriter": "...", "handwriting": "..." },
  "brand": {                                  // normalised: lowercase six digit hex
    "primary": [{ "name": "Orange", "value": "#ff6a13" }], "secondary": [], "accent": [],
    "neutral": { "light": "...", "dark": "...", "surface": "...", "muted": "..." }
  },
  "types": [{ "name": "repo", "label": "Repository", "dot": "secondary.0" }],  // overrides applied
  "defaultCollection": "tools",
  "collections": [{
    "id": "tools", "title": "...", "short": "...", "description": "...",
    "tags": ["python"],                       // sorted, distinct
    "items": [{
      "id": "uv", "key": "uv", "no": "01",    // key is the item title, the seed for every hash
      "title": "uv", "url": "https://example.com/uv", "domain": "example.com",
      "type": "repo", "tags": ["python"],
      "notesHtml": "<p>...</p>", "notesText": "...",
      "image": { "src": "/images/<hash>.jpg", "width": 1200, "height": 630, "fit": false },
      "poster": null                          // set instead of image when there is none:
    }]                                        // { "v": 0 to 15, "set": "light" or "inverse", "paper": "#..", "inks": ["#..", "#..", "#.."], "band": "#.." }
  }]
}
```

Exactly one of `image` and `poster` is set on every item. `image.src` is a `/images/<hash>.<ext>` path for a raster image and a `data:image/svg+xml;base64,` address for an uploaded SVG, so no `.svg` file is published. The page head of an item with a `data:` address uses `site.socialImage` for its card. Collections are in display order. `core.js` adds fields at load time: `index` on collections and items, `col` (the collection id) on items, and `?stress=1` copies. Changing the shape means changing `site.mjs`, the code that reads it, the tests and this section.

## 6. Front End

`src/index.html` loads `base.css`, the scene's `scene.css`, the theme block and `core.js` as a module. It carries `<meta name="curator-assets">`, which `core.js` reads to find the hashed asset folder. `core.js` runs `boot()` and is responsible for the following.

**Data load and the ready marker.** `boot()` fetches `/data/site.json`. If it fails or has no collections, it shows "This site could not be loaded." and records the error. Errors, including uncaught ones and rejections, are written to the `data-errors` attribute of `<html>`, which tests read to fail on any front end error. After the data loads, `core.js` applies `?stress=1`, builds the grain texture, creates the API (`createApi()`), imports `scenes/<scene.name>/scene.js` from the hashed folder, awaits `mount()`, then renders the screen reader list. When the scene calls `api.ready()`, `<html data-ready="1">` is set, which is the signal that screenshots and tests wait for.

**Routing.** URLs are real paths, so every route is a real file: `/`, `/<collection>/` and `/<collection>/<item>/`. `route()` parses `location.pathname` into `{ col, item, notFound, home }`, ignoring a trailing `index.html`. `go()` and `open()` use `history.pushState` and mark an item entry with `{ cuItem: true }`. `replace()` uses `history.replaceState` and is what the projector uses to page between items, so one open session is one history entry. `close()` calls `history.back()` when the current entry is marked and otherwise replaces the URL with the collection. `popstate` and every navigation go through `fire()`, which syncs the tab title and calls the scene's route callback. The query string is kept on every navigation. Old hash links such as `#/tools/uv` are rewritten to paths with `replaceState` at the start of `boot()`, before routing. A path that is not a known collection, an unknown item, or a path with more than two segments is not found. For it, `boot()` calls `toHome()` (a `replaceState` to `/` with the query kept) before the scene mounts, so the scene shows the home table, then shows a dismissible note "Page not found." with `role="status"`.

**Tab title.** `syncTitle()` sets `document.title` with `pageTitle()` on every route change. A not found path is replaced by home first, so its title is the site title.

**Filter.** `mountTags(host, collection, onChange)` renders an `all` chip (`data-tag=""`) followed by one chip per tag, keeps a single active tag, sets `aria-pressed` and calls `onChange(tag or null)`. `all` is pressed whenever no tag is active and clears the filter when clicked. Clicking the active tag also clears it. A collection with no tags gets no chips and the host is hidden. The group is labelled "Filter by tag" and has no visible label. `matches(item)` answers whether an item passes the current filter. The scene decides how to show it, and the light table dims non matching slides. Because a table shows one page of slides at a time, `tagNote()` in the scene fills a marigold pill, `.tb-more`, with "Tagged: N. More on other pages" when the filter has matches that are not on the current page. The pill is absolutely placed at the top of the glass, inside the slides' top padding, which is sized to hold it whether or not it shows, so no slide moves. The filter resets when the table changes, and every other table's dimming and note are cleared. On phones the chip row scrolls sideways: the row fades at a clipped edge and a chevron button on each side (`#chips-l`, `#chips-r`) scrolls the row by most of its width. A button is dimmed away at its end, and both keep their space so scrolling never resizes the row. They are level with the chips. On wider screens the chips wrap onto as many rows as they need, and `layout()` follows the heading height.

**Motion.** `createApi()` computes three things. `still` is true with `?still=1`. `reduced` is true for `still`, for `advanced.scene.motion: "off"` and for the OS reduced motion setting. `k` is 0.6 for `fast` and 1 otherwise. For `still` and `off`, the `cu-still` class on `<html>` also switches off CSS transitions and animations, and `base.css` does the same under `prefers-reduced-motion`. `?stress=1` pads every collection to 80 items by cloning (ids get a numeric suffix and keys become `title#n`) so paging and performance can be tested. The helpers `dur()`, `wait()` and `anim()` apply `k` and `reduced` in one place. `anim()` uses the Web Animations API and resolves with a timer fallback, a race between `animation.finished` and a timeout of duration plus delay plus 80ms, because `finished` never settles when a browser stops drawing frames (background tabs and headless runs). When motion is reduced, `anim()` jumps to the last keyframe and `wait()` resolves at once. Scenes must use these helpers and never rely on `animationend` or `finished` alone.

**Top bar.** `chrome.mount()` prepends the `<header class="cu-top">` with the wordmark link (a plain click goes to the default collection through `go()`, a modified click follows the link) and the collections menu: a hamburger button (`.cu-menu-btn`, with `aria-expanded` and `aria-controls`) and a hidden `<nav id="cu-menu-panel" class="cu-cols">` of `.cu-col` buttons, one per collection. Opening focuses the current row and fades the panel in over 160ms through `anim()`. Choosing a row, Escape, a click outside, tabbing out and any route change close it (the router calls the close in `fire()`). A capture phase `keydown` handler on `document` handles Escape and the arrow keys while the menu is open and stops them, so they never reach the scene handler. `chrome.mark(id)` sets the current row and `aria-current`. `swipe(el, fn)` turns a horizontal touch swipe into a direction for collection changes.

**Screen reader list.** `renderList()` appends a visually hidden `<nav class="sr-only" aria-label="All items">` after the scene mounts. It holds every item of every collection with its title (linking to the item path), type label, notes and a Visit link. Its links have `tabindex="-1"` because they have no visible focus ring. It must never get a `content-visibility` rule, because a skipped subtree is missing from the accessibility tree.

## 7. Scene Contract

A scene is a folder `src/scenes/<name>/` with `scene.js` and `scene.css`. `scene.js` exports `async function mount(root, site, api)`. `root` is the `#app` element, `site` is the loaded `site.json` object and `api` is the object below. `core.js` awaits `mount()`, so a scene may do async work first.

| `api` member | Purpose |
|--------------|---------|
| `route()` | The current route `{ col, item, notFound, home }`. Use it for the first route |
| `onRoute(fn)` | Registers the one route callback. Called after every `pushState`, `replaceState` and `popstate`, with a route object |
| `open(item)`, `close()`, `go(colId, itemId)`, `replace(item)` | Navigation. `open` pushes an item entry, `close` steps back or replaces, `go` changes collection or item, `replace` pages to another item without a new history entry |
| `toHome()` | Used by the core for not found paths. A scene does not need it |
| `mountTags(host, col, onChange)`, `matches(item)` | The tag filter (section 6) |
| `chrome.mount()`, `chrome.mark(colId)` | The top bar. Call `mount()` once and `mark()` when the collection changes |
| `swipe(el, fn)` | Touch swipe helper |
| `anim(el, frames, opts)`, `wait(ms)`, `dur(ms)` | Motion helpers that honour `motion` and reduced motion and have timer fallbacks |
| `reduced`, `still` | Booleans for the motion state, for branches the helpers cannot cover |
| `visual(item, w, h)` | HTML for the item's picture: an `<img class="vis-img">` (with `vis-fit` when `fit` is set, lazy loaded) or an inline poster SVG |
| `typeLabel(type)`, `typeDot(type)` | The configured label, and the `var(--dot-<type>)` colour the build wrote for the type |
| `esc`, `hash`, `num(item, salt, lo, hi)`, `pick(item, salt, list)` | Escaping and deterministic per item variation, so slides keep their look |
| `ready()` | Marks the page ready |

**Core owns:** data loading, routing and history, the tab title, the not found note, the tag filter state, motion rules, the top bar, the grain texture, the screen reader list and the ready marker. **The scene owns:** layout, its markup and CSS, all visual state, motion choreography, paging inside a collection, focus management and keyboard handling for its own controls, and the focus trap of any modal layer it opens. Each scene must keep the accessibility rules in section 8.

**`api.ready()`.** The scene calls it once its first route is fully applied. For a deep link to an item, that means the screen is open. The light table does `onRoute(api.route(), true).catch(() => {}).then(api.ready)`. Call it even if the first route fails, so waiters do not hang.

**Adding a scene.**

1. Create `src/scenes/<name>/scene.js` with `mount()` and `src/scenes/<name>/scene.css`. The template links `scene.css` for the chosen scene.
2. Declare scene colours as CSS tokens in a `:root` block of `scene.css` (section 9). The build reads them from there for validation and for the docs.
3. Set `advanced.scene.name` to `<name>` in `curator.config.json`. The schema only checks that it is a lowercase id, and the build does not check that the folder exists, so a typo shows up as a front end error in `data-errors` and a page that does not load.
4. Use `api.typeDot()`, `api.visual()` and the motion helpers rather than reimplementing them.
5. Add or extend browser tests. The existing pages in `tests/browser/` select light table elements, so a new scene needs its own pages, or a harness that is scene aware.
6. Update `scripts/docs-config.mjs` `GROUPS` if the scene's token groups are new, then run `npm run docs`. Update this file.

The build only ships the files of `src/`, so every scene in `src/scenes/` is copied to `dist/assets/<hash>/scenes/`, used or not.

## 8. The Light Table Scene

`src/scenes/lighttable/scene.js` is one `mount()` function. `MARKUP` is inserted into `#app`: the room with its `rail`, the heading with the filter chips, the two side arrows and the hidden `booth` dialog. The rest of the file is a set of small functions over a few variables.

**Backdrop and heading.** The beige grainy backdrop (`page-room`, `page-room-glow`, `page-room-edge`, plus the grain) is painted on `body.lt-page`, not on the scrolling room. The room has a mask that fades slides out under the heading as they scroll, so the heading sits straight on the backdrop with no banner. Title, description and wordmark use `--head-ink` and `--head-dim`. From 901px wide the title sits level with the wordmark and the menu button (`--h1` sets its offset), with a gap above the bar equal to the one between the chips and the table (`--head-gap`, 24px). Below that width it stays under the bar with no extra gap. Tag chips, the menu button, the menu panel and the notice keep a solid dark fill (`--chrome-chip-fill`) so they read on the light backdrop. The booth has a solid base (`--page-booth-base`) under its dim gradient.

**Rail and tables.** One `<section class="table">` per collection sits side by side in the rail, with a gap (`--gap` on `.lt-rail`) wide enough that every neighbour starts past the viewport edge, so only the current table is ever on screen. Each holds a `.slides` grid with one `<button class="slide">` per item (labelled with title, type and domain) and a plate with the collection name, the visible range and two page buttons. `slideHTML()` builds a slide from the item: mount style by type and hash, label font, window with `api.visual()` and the type dot. The label shows the title cut at the last whole word within a character limit for its style (`LABEL_MAX`: 36 handwritten, 45 typed, 32 typed on the grey plate, 45 handwritten on the grey plate), with a trailing small word or punctuation dropped. The limits were measured on the default fonts with a margin, because the handwriting's tight line height makes a CSS clamp either trim descenders or show the next line. The full title stays in the slide's accessible name and on the screen. Slide rotation and offset come from `api.num()`. `layout()` reads that gap from the computed style, sets `--rx` to slide the rail by one table width plus the gap and `--headH` for the heading height. `setTable(index, instant)` makes one table current: it marks `.on`, makes every other table's slides and plate `inert`, fills the heading, remounts the filter chips, updates the arrows' `aria-disabled` and scrolls the room to the top. Images of tables other than the current one wait in `data-src` until an `IntersectionObserver` sees them or the table is selected, because native lazy loading also fetches images well off screen.

**Paging.** A table shows `advanced.scene.pageSize` slides. `showPage()` toggles the `off` class on slides outside the page and updates the range text and the page buttons' `aria-disabled`. Slides keep their place in the grid markup, so hidden pages cost no animation. `changePage()` slides the grid out and the next page in over about 400ms, only on the `.slides` element. **Every table is as tall as a full page**, so tables never change height and all of them match. `fitPages()` measures one real slide, reads the column count from the computed grid, works out the rows for `pageSize` and sets the same `min-height` on every `.slides` grid, with the spare room under the last row. `layout()` runs `fitPages()` again on window resize (debounced 80ms), when fonts finish loading, on window load and when the heading size changes. Page buttons and arrows use `aria-disabled` and stay focusable. If the projector pages past the table's page, `closeSlide()` first shows the page that holds the current slide.

**Booth sequence.** `onRoute()` chains every route change on one promise (`busy`), so transitions never overlap. Opening (`openSlide()`) fills the screen, shows the booth, makes everything outside it `inert`, then plays: the slide lifts (`geom()` copies the slide into the flying clone with its ids renamed (a poster's clip paths are found by id, and the copy would otherwise use the hidden slide's, which clip everything away), and computes the flight path), the room darkens and the projector rises, the slide flies to the gate, the screen unrolls, the lamp and beam come on (`placeBeam()`), the image comes into focus, the caption fades in, and focus moves to the screen body. Projector advance (`swapSlide()`, triggered by `page()` through `api.replace()`) keeps the screen down and takes about 450ms: the image dims, the lamp flickers, the new item is filled in place and focuses in. `want` remembers the latest requested target so quick key presses chain from the pending item. Closing (`closeSlide()`) plays the opening in reverse, removes `inert`, clears the live region and returns focus to the slide. A scene running `?still=1`, `motion: "off"` or reduced motion skips the animated steps through the helpers, and every step has a timer fallback.

**Focus trap, live region and keyboard.** While open, the booth is a modal `role="dialog"` named by the item title (`aria-labelledby="cp-title"`). A document level `keydown` handler cycles Tab and Shift+Tab through the booth's tab stops (`tabStops()`), including from the screen body, which is not a tab stop. Left and Right page the projector and briefly show the matching button pressed (`pressed()`). Escape calls `api.close()`. The round knob on the projector (`#pj-power`, `aria-label` "Turn off the projector") closes the screen through `api.close()`, exactly like "Back to the table". It is a tab stop, so the booth Tab order is Visit, previous, next, power, close. Each paged slide is announced through a polite `role="status"` live region inside the booth, for example "Ruff, slide 02 of 16". On the table, arrows move focus between the slides of the current page (Up and Down pick the nearest slide in the next row), Shift with Left or Right and PageUp and PageDown switch collection, and Enter or Space activates the focused slide because slides are real buttons. The handler ignores keys inside the top bar, the chips and the page buttons, so their own behaviour stays intact.

## 9. Design Values

**Colour tokens.** Every scene colour is a CSS custom property with its default value, declared in a `:root` block of `src/css/base.css` or `src/scenes/<name>/scene.css`. Each token is one line, `--group-name: <colour>` followed by a one line `/* what it colours */` comment, and the comment becomes the Colours column of `docs/CONFIG.md`. The group is the first word of the name (`page`, `chrome`, `button`, `table`, `glass`, `mount`, `label`, `screen`, `caption`, `beam`, `projector`), and tokens are listed grouped by object. `tokensFromCss()` in `scripts/lib/theme.mjs` reads them and keeps only values that `isColor()` accepts (hex of 3, 4, 6 or 8 digits, `rgb()`, `rgba()`, `hsl()`, `hsla()` with plain numbers, or `transparent`), and `collectTokens()` gathers `base.css` and the active scene. The same list feeds validation and `docs/CONFIG.md`, so a token without the right shape is invisible to both. Shadows and highlights may stay pure black or white with alpha. Non colour variables, such as font stacks and easing, live in a separate `:root` block and are not tokens.

**Brand driven role tokens.** A few roles follow the brand and cannot be overridden: `button-visit-fill`, `-hover`, `-pressed` and `-text`, `chrome-pill-on-fill`, `chrome-pill-on-text` (the active collection menu item), `chrome-focus`, `chrome-arrow-fill` and `chrome-arrow-icon` (the list is `ROLE_TOKENS`). `computeRoles()` computes them: the fill of the Visit button and of the active collection menu item, the focus ring and the fill of the round side arrows are accent 1, else primary 1, Visit hover and pressed are shades of that fill, the Visit and menu item text is the dark or light neutral that contrasts more with it (black or white with a warning when neither reaches 4.5 to 1), and the arrow icon is the dark or light neutral that contrasts more with that fill (black or white with a warning when neither reaches 3 to 1). It also resolves each type's dot role (such as `primary.1`) to a colour, with the first colour of that tier as fallback. `themeStyle()` writes all of it, plus `--dot-<type>` for every type, into the `<style id="curator-theme">` block, which comes after the CSS links so it wins. The defaults in `base.css` for those tokens are only fallbacks.

**Overrides and validation.** `advanced.scene.colors` maps a token name (no leading dashes) to a colour. `validateColors()` rejects an unknown token, a role token or a value that is not a colour, and `themeStyle()` writes only values that pass, so a bad value can never reach a page.

**Fonts.** There are six roles. `display` (titles, wordmark), `body`, `mono` and `poster` are under `basic.fonts`. `typewriter` and `handwriting` are under `advanced.fonts`. `themeStyle()` turns each into a CSS variable (`--f-serif`, `--f-sans`, `--f-mono`, `--f-poster`, `--f-type`, `--f-hand`) with a fallback stack, and `core.js` builds the poster fonts from `site.fonts`. Fonts load from the hosted font service by default (`fonts.source: "google"`, `display=swap`, a generated URL or `googleFontsUrl`) or are downloaded and served from `dist/fonts/` with `fonts.source: "self"`, so the site makes no third party requests (section 3, step 4). `docs/CONFIG.md` has the details of every key.

**Posters.** Items without an image get a deterministic inline SVG poster. `buildPalette()` in `palette.js` makes two ink sets: a light set (light neutral or surface paper with brand inks) and an inverse set (the dark neutral or a primary as paper, used by about `inverseShare` of items). Rules for each poster: at least one primary ink, three distinct inks, no `avoidPairs` pair together, every ink at least `minContrast` against the paper, and `excludeFromPosters` colours never used. A primary is only used as paper when another primary still reads on it. The title band ink is the first own ink reaching 4.5 to 1, else the dark or light neutral. To reach `primaryShare` across a collection, `buildPalette()` tries a ladder of primary weights (`WEIGHTS`) against 240 sample keys and keeps the closest. `palette(key)` is a pure function of the key. `kit.js` has 16 compositions, numbered 0 to 15 in code and 1 to 16 in `advanced.posters.compositions`. `assignPosters()` gives every item in a collection a different composition until all allowed ones are used, then repeats. The build assigns per collection among poster items only. `docs/CONFIG.md` lists the poster settings.

## 10. Extending

**Add a content type.**

1. Add an entry to `TYPES` in `src/js/types.js`, before `webpage`: `{ name, label, dot, match }`. `dot` is a colour role such as `accent.0`, and `match` receives a `URL` and returns true. Use the exact or dot suffix host match (`hostIn()`), never a substring.
2. Everything else follows from the registry: `inferType()`, the `type` validation message, `site.types`, the `--dot-<name>` variable and the `advanced.types` overrides.
3. Slides get a `t-<name>` class. `slideHTML()` in the light table has a `mounts` map by type for slide mount styles and falls back to a plain card, so add the type there to give it its own look.
4. If the type needs its own preview image rule, add it in `scripts/lib/images.mjs`.
5. Add cases to `tests/types.test.mjs` and update `docs/GETTING-STARTED.md` or this file if the list of types is documented.

**Add a setting.**

1. Add it to `src/config.schema.json` in the right place under `basic` or `advanced`, with `type`, a `default`, a plain language `description` (it becomes the Meaning column of `docs/CONFIG.md`) and a `message` where the default error is unclear. Objects set `additionalProperties: false`.
2. Read it where it is used. If the front end needs it, copy it into the data object in `buildSiteData()` (`scripts/lib/site.mjs`) and document the field in section 5. Cross field checks and warnings go in `validateSite()`.
3. Run `npm run docs`. `tests/docs.test.mjs` fails when `docs/CONFIG.md` does not match the generator output.
4. Add a unit test for the schema rule and for the behaviour.

**Add a scene.** See section 7.

## 11. Testing

Run everything with `npm test` (units) and the browser commands below. A change is not done until the relevant ones pass.

**Unit tests.** `npm test` runs `node --test`. Files are `tests/*.test.mjs`, one per area: parser, markdown, validation, config, build, check, images, image sizes, fonts, theme, palette, kit, types, the dev server, the static server, the DevTools driver and the generated docs. Conventions:

- Only `*.test.mjs` files are found by the runner. Browser pages and scripts in `tests/browser/` and fixtures in `tests/fixtures/` are named so they never match.
- Tests never touch the repo's `content/`, `dist/` or `.cache/`. They copy a fixture from `tests/fixtures/` into a folder made with `mkdtempSync(join(tmpdir(), 'curator-...'))`, build there, and remove it in an `after()` hook.
- Tests never use the network. Set `advanced.images.fetch` to false, pass `offline: true`, or inject a fake `fetchImpl` into `resolveImages()`, `resolveFonts()` and `buildSite()`.
- Each fixture has its own `curator.config.json` and `content/`, so a test controls exactly the errors and warnings it expects.
- The palette tests check the rules for both the default brand and `docs/examples/sample-brand.json`.

**Browser tests.** `npm run test:browser` (`scripts/browser.mjs`) runs real pages in a headless Chromium based browser. `findBrowser()` in `scripts/lib/headless.mjs` finds it, and `CURATOR_BROWSER` points at a specific binary.

- **Driver.** `scripts/lib/cdp.mjs` is a small DevTools Protocol client with its own WebSocket framing and no dependencies. `launch()` starts the browser with a temp profile, and `newPage()` gives `goto`, `evaluate`, `press`, `screenshot`, `waitFor`, event subscription and `close`. It runs in real time, never in virtual time, so timers, fonts and layout behave as for a user. `press()` sends real key events (`keyEvents()`), so focus really moves and Tab really cycles.
- **Pages.** Each test is `tests/browser/<name>.html` with a `<pre id="R">pending</pre>` and `harness.js`, which exposes `H.run(name, body)`. The body gets `t`: `t.load(src, width, height)` loads the site in a same origin iframe, `t.check(name, pass, detail)` records a result, `t.press(key)` sends a real key press, `t.axTree()` returns the accessibility tree, `t.cdp(method, params)` makes an allowed DevTools call (for example `Emulation.setEmulatedMedia` for reduced motion), `t.site()` loads `site.json` and `t.sleep` and `t.waitFor` poll. The harness adds a check that no front end error was recorded in `data-errors`, then writes one JSON result into `#R`. The scripts `contrast.js`, `reduced.js`, `tableheight.js` and `onetable.js` hold the larger bodies.
- **Request bridge.** A page cannot send real input, so it queues a request with `H.take()` and `H.give()`. The runner (`serve()` in `scripts/browser.mjs`) polls the page, runs the request and answers. Only `press`, `Accessibility.getFullAXTree` and `Emulation.setEmulatedMedia` are allowed.
- **Sites.** The runner builds a temp copy of the repo content and config offline, with the image and font caches copied in, so it never overwrites `dist/` or a running `npm run dev`. It serves the build on a free port with the `/__tests/` mount, and blocks every host except localhost, so tests never depend on the network and run on fallback fonts. Pages listed in `OWN_SITE` get their own temp build. `motionoff` and `types` build the repo content with an `advanced` override. `tableheight` and `tableheight4` build `tests/fixtures/tables/`, which has collections of 16, 9 and 5 items, so they always have one collection longer than a page and one shorter, whatever the repo content holds. `tableheight4` also sets `pageSize: 4`.
- **Options.** `--only <name>` runs one page. `--url <base>` tests an already running site such as `npm run dev` instead, and then the `OWN_SITE` pages run against that site and need it to be built with the override they expect. Each page has a 60 second limit.
- **Adding a test.** Copy a small page such as `tests/browser/disabled.html`, add its name to `ALL` in `scripts/browser.mjs`, and add it to `OWN_SITE` if it needs different config (`advanced`) or content of a known shape (`fixture`, a folder in `tests/fixtures/`). A test that depends on how many items a collection has should use a fixture, because the repo content changes. Use real `.click()` calls and real key presses, not only deep links, because deep links skip the click path.

The pages cover: click open and close with focus, projector paging, table paging and page sync, deep links, the filter, the back button, keyboard and focus trap, the modal dialog name and live region, disabled controls, the accessibility tree, contrast, reduced motion and `motion: "off"`, tab titles, tap targets, table heights (also at `pageSize` 4), routes and not found, type overrides and the heading height.

**Screenshots.** `npm run shots` (`scripts/shots.mjs`) writes PNGs to `.cache/shots/` (`--out` to change, `--url` to use a running site): the table, an open image item and an open poster item (the first of each in any collection) at 1440x900 and 1280x720, a stress table, the not found page and a phone page. The phone shot loads `/__tests/phone.html`, which embeds the site in 390px wide iframes, because headless browsers will not lay out narrower than about 500px. The readiness rules, run inside the page, are: wait for `html[data-ready="1"]` in every frame, `readyState` complete, every font loaded and stable, every wanted image complete and decoded (skipping lazy images off screen and `data-src` images that are not woken), then two frames and a short pause. Pages open with `?still=1` so animations never block them. Never use virtual time, because it skips the real timers and loads that the rules wait for. Failed images are reported as warnings.

**Performance.** `npm run perf` (`scripts/perf.mjs`) builds temp variants (default fonts, self hosted fonts and `pageSize` 4) and measures in real motion: the transfer size of `/` before images and webfonts, judged against a 300 KB gzip budget and reported for both font sources, the image requests on load and after paging and switching tables (none for hidden pages and tables off screen), frame times for the table page, open, projector advance and close at `/?stress=1` with and without a 4x CPU throttle, and that no animation runs on hidden pages or in inactive tables. Smoothness is judged only unthrottled. Options are `--only transfer,lazy,smooth,hidden`, `--runs <n>`, `--json <file>`, `--path` and `--url`.

**Known headless quirks.** Animations never finish in headless mode, so use `?still=1` for screenshots. Every animation has a timer fallback, so functional tests still complete. The scene builds after fetching `site.json`, so the load event fires before any slide, image or web font exists. Wait for `html[data-ready="1"]` before judging a page, and treat a blank or broken image after that as a real failure. The open screen at 1280 can differ by a few thousand pixels inside the projector beam between screenshot runs, from how Chromium composites its blend mode. Everything else should be identical.

**Hand checks.** Some things only a real browser or device shows: the feel of the opening, closing, paging and projector motion in several browsers, real phone layouts, assistive technology, `?stress=1` smoothness, reduced motion at the OS level, a social card preview and a live deploy. Check the ones your change touches by hand where you can. The live site checks are in [Check the Live Site in DEPLOY.md](DEPLOY.md#check-the-live-site). Say in your change description what you could not verify, especially motion.

## 12. Rules for Changes

- **No runtime dependencies.** Dev dependencies need a clear reason, stated with the change.
- **Plain JavaScript.** ES modules only, with no framework, bundler or TypeScript.
- **Shared modules stay DOM free.** `types.js`, `seed.js`, `palette.js`, `kit.js` and `title.js` never touch the DOM and never import `node:` modules.
- **No hard coded colours or timings in components.** Every colour, font and timing comes from config or a CSS custom property with a default. A new colour is a new token with a one line comment, followed by `npm run docs`.
- **Copy.** Visible text and documentation never use em dashes, en dashes or semicolons. Use commas, colons or separate sentences. Never name a real company, brand or platform in code, tests or docs. Example brands are called "Sample brand" and example URLs use `example.com`.
- **Markdown docs** are softwrapped, with each paragraph as one line.
- **Comments** are one line and state a constraint at the point of use. Reasoning belongs in the docs.
- **Keep this document true.** When behaviour changes, update this file in the same change, and run `npm run docs` when the schema or a colour token changes.
- **Accessibility is part of behaviour.** Disabled controls use `aria-disabled` and stay focusable. Focus is always visible. Everything outside an open modal layer is `inert`. Every item stays in the screen reader list.
- **Do not commit unless asked.**

Before you hand over a change:

1. Run `npm test` and `npm run check`.
2. Run `npm run test:browser`. The click, Escape, projector paging and table paging pages must pass.
3. Look at screenshots from `npm run shots` of the table and an open item at 1440x900 and 1280x720, and at phone width.
4. Run `npm run perf` if you touched anything that loads, animates or paginates.
5. Report what you verified and what you could not.
